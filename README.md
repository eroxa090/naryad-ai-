# НарядAI

Система выдачи и контроля нарядов с ИИ для ремонтных служб АО «Костанайские минералы».
Qostanai AI Industry Hackathon 2026, **кейс 1**.

**Рабочая версия:** https://naryadai-kz.vercel.app  
**Telegram-бот:** [@naryad_ai_kz_bot](https://t.me/naryad_ai_kz_bot)

В базе ~600 демонстрационных нарядов за 90 дней, 19 сотрудников, 4 участка и 30+ единиц оборудования.

## Проблема

Наряды выдают по рации и на бумаге. Срочные работы ждут, факт и качество выполнения никто не подтверждает, повторные поломки и узкие места не видны.

## Что умеет система

| Требование кейса | Как реализовано |
|---|---|
| Выдача нарядов | Панель мастера: показатели смены, люди на смене, канбан по статусам, фильтры. Новый наряд голосом: Whisper распознаёт речь, ИИ заполняет участок, оборудование, шифр неисправности, тип работ и приоритет, подсказывает исполнителя по специальности, разряду, очереди и рейтингу |
| Мобильное приложение исполнителя | PWA без установки из магазина. Самый срочный наряд сверху, таймер до срока, крупные кнопки под перчатки, офлайн-очередь действий (IndexedDB) |
| Уведомления | Telegram-бот: новый наряд с кнопками «Принять / В очередь / Начать», `/my`, вопросы «кто свободен?», «что просрочено?» |
| Контроль сроков | Проверка каждую минуту на сервере (pg_cron): напоминание за 30 минут, уведомление о просрочке, эскалация мастеру, если наряд не принят (аварийный — 3 мин, остальные — 10 мин), с предложением свободного исполнителя |
| Проверка выполнения | Фото «до / после», материалы, шифр. Правила проверяют полноту, время против норматива и расход материалов. Антифрод: EXIF и перцептивный хэш (повтор фото из других нарядов). Мультимодальная модель сверяет фото с описанием работ. Итог — оценка 1–5 и вердикт; на доработку отправляется автоматически, закрывает наряд мастер |
| Рейтинг исполнителей | 35% качество + 25% в срок + 20% без возвратов + 15% сложность − 5% штраф; сравнение бригад |
| Отчёты | KPI за период, оценка простоя, ИИ-сводка смены, экспорт в Excel и PDF |
| Аналитика аномалий | Самое проблемное оборудование, повторные отказы, поломки после ППР, отклонения по сменам, исполнителям и материалам, еженедельная сводка |
| Прогноз отказов | Карта здоровья оборудования: риск отказа по каждой единице |
| Дополнительно | QR-коды на оборудовании (печать и сканирование), интерфейс RU/KZ, роли и RLS на уровне БД |

## Как устроен ИИ

- **Детерминированные правила работают всегда**, даже без ИИ: полнота, нормативы, материалы, антифрод, статистика аномалий. Языковая модель добавляет проверку смысла и фото, формулировки рекомендаций и сводки.
- Модели: Claude (Anthropic) — проверка нарядов, разбор текста, сводки, ассистент; Whisper large-v3 (Groq) — распознавание речи. Ответы модели проходят валидацию по схеме (zod).
- **Персональные данные не уходят в ИИ:** ФИО заменяются кодами сотрудников.
- **Решение всегда за человеком:** ИИ рекомендует, мастер принимает или возвращает наряд.
- Режим `AI_MOCK=true` позволяет запускать всё без ключей и без затрат.

## Архитектура

```
PWA (React + Vite)  ──►  Vercel Functions (/api)  ──►  Claude API, Groq Whisper
        │                       │                          Telegram Bot API
        └──── Supabase: Postgres + RLS, Auth, Realtime, Storage, pg_cron ◄┘
```

**Стек:** React 19, TypeScript, Vite PWA, TanStack Query, Dexie, i18next, Supabase, Vercel Functions, Telegram Bot API, sharp, Recharts, jsPDF.

```
src/            фронтенд: pages/ (экраны), components/, lib/ (api, офлайн, QR, i18n)
api/ai/         проверка наряда, разбор текста, подбор исполнителя, речь, сводка, ассистент, аналитика
api/cron/       контроль сроков и ежедневная аналитика
api/telegram/   webhook бота
shared/         общие типы фронтенда и API
supabase/       миграции SQL и генератор демо-данных
```

## Запуск локально

1. `npm install`
2. Скопировать `.env.example` в `.env` и заполнить ключи.
3. Supabase → SQL Editor: выполнить по порядку `supabase/migrations/001_init.sql`, `003_reset_demo.sql`, `004_fixes.sql`.
4. Демо-данные: `npm run seed`.
5. Фронтенд: `npm run dev`. Фронтенд вместе с `/api`: `npx vercel dev`.

## Деплой

1. Vercel → Import Git Repository → добавить переменные из `.env.example` → Deploy.
2. В `supabase/migrations/002_cron.sql` подставить `APP_URL` и `CRON_SECRET`, выполнить в SQL Editor.
3. Webhook бота:
   `curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=<APP_URL>/api/telegram/webhook&secret_token=<CRON_SECRET>"`
4. Сотрудник привязывает Telegram: `/start <логин>`, затем PIN.
